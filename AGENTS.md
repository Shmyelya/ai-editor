# Правила работы над проектом

Это правила агента для AI-редактора текста. Источник задачи — `docs/TASK.md`. План шагов — `docs/PLAN.md` (составляется отдельно). Если требование здесь расходится с догадкой, выполняется этот файл. Где задание оставляет выбор, выполняется решение из этого файла.

Неясное спрашивать. Не додумывать экраны, тексты, API-поля и шаги, которых нет в задании, в этом файле или в плане.

Стартовая точка — текущее приложение-чат в `test/`. Новый проект не создавать.

## Зафиксированные решения

- Swift 6, SwiftUI, минимальная iOS 18.0. Приложение собирается и работает и на iOS 18, и на актуальной iOS. API новее iOS 18 не использовать.
- Только iPhone. Bundle ID `com.yelzhanyelikbayev.aieditor`. Отображаемое имя — «AI-редактор». Проект, схема и таргет — `test`.
- MVVM и `@Observable`. История правок — SwiftData, переживает перезапуск.
- Зависимостей нет: ни CocoaPods, ни пакетов Swift Package Manager.
- Сеть только через `URLSession`. Ответ модели — поток SSE. На каждый запрос создаётся новая `URLSession`, таймаут запроса — 15 секунд. Общую сессию не вводить.
- AI: Groq, `POST https://api.groq.com/openai/v1/chat/completions`. Имя модели — одна константа со значением `openai/gpt-oss-120b`. Строку модели не дублировать. В теле запроса `stream: true` и `reasoning_effort: "low"`. Ключ передаётся заголовком `Authorization: Bearer`.
- Запрос к модели — системное сообщение с промптом выбранного действия и сообщение пользователя с исходным текстом. Других полей в теле нет.
- В результат и в историю пишется только текст ответа пользователю. Отдельные дельты рассуждений модели, если они приходят в SSE, на экран и в SwiftData не попадают.
- Проект описывает `project.yml` в корне. `xcodeproj` вручную не менять: его генерирует XcodeGen. Каталог `*.xcodeproj` остаётся в `.gitignore`.
- Корень репозитория — сама папка проекта. Исходники таргета лежат в `test/`. Перенос файлов только шагом плана.

## Что переиспользовать

Оставить и подогнать под редактор, не писать заново:

- `GroqChatService`: адрес Groq, поток SSE, отмена запроса, новая сессия на запрос, таймаут 15 секунд.
- Разбор сбоев: «нет сети», «кончился лимит API» (HTTP 429 и ответ Groq об исчерпании квоты или лимита), прочий сбой запроса.
- Поведение «Стоп» и «Повторить».

Чат-промпт из `GroqChatService` убрать: он разрешает разметку. Экраны чата заменить. Модели чата и прочий код чата, который редактору не нужен, удалить. Отдельного чата в приложении не остаётся.

## Секрет

Файл: `test/Services/Secrets.swift`.

Соль — строковая константа `test.groq.v1` (байты UTF-8) в этом же файле. Обфусцированный ключ — `static let obfuscatedKey: [UInt8]`. Байт `i` исходного ключа кодируется так:

`obfuscated[i] = keyUTF8[i] ^ saltUTF8[i % saltUTF8.count]`

Декодирование — тот же XOR. Пример для одного байта: символ `A` (`0x41`) и первый байт соли `t` (`0x74`) дают `0x35`.

Ключ не запрашивать и не искать. В репозиторий, логи, README и ответы не попадает открытый ключ. Массив байтов вставляет пользователь. Пустой массив или заглушка означают, что шаг с ключом не готов. Декодированная строка живёт только в памяти на время запроса: не писать её в логи, UserDefaults и SwiftData.

## Как работать

1. Следующий артефакт — `docs/PLAN.md`. Код приложения до отдельной просьбы выполнить шаг плана не писать.
2. Идти по шагам плана по порядку. Один шаг за раз. Шаг не расширять соседними задачами. Шаги мелкие: на всё задание 4 часа.
3. Конец шага: успешная сборка схемы `test` под симулятор iPhone и один git-коммит этого шага. Сломанную сборку не коммитить. Git config не менять, хуки не отключать, на remote не пушить без явной просьбы.
4. В корне лежит `Build.command`. Двойной клик в Finder запускает `xcodegen generate` и собирает схему `test` под симулятор iPhone, без команд в терминале. Когда файл уже есть, им и проверять шаг.
5. Расширение «Поделиться», версия для Mac и выбор тона в объём не входят. Они появляются только отдельным пунктом `docs/PLAN.md`, который пользователь явно подтвердил. Если время останется, первый такой пункт — выбор тона для перефразирования.

## Функциональные требования

Приложение открывается сразу после сборки, без экрана настроек и ввода ключа.

Экраны ровно три:

- Редактор: ввод текста, выбор действия, язык для перевода, запуск, «Стоп», результат, копирование результата.
- История правок.
- Просмотр одной правки из истории.

Отдельных экранов сверх этих трёх нет. Просмотр открывается из истории. Как устроен переход, какие пустые тексты сверх обязательных кнопок и как называются типы SwiftData — в `docs/PLAN.md`, внутри этих требований.

Действия ровно четыре: перефразировать, сократить, перевести, исправить ошибки. У каждого свой системный промпт. Промпт требует вернуть только итоговый текст, без вступления, пояснений и разметки. Дословные строки промптов фиксируются в `docs/PLAN.md`. До подтверждения плана эти строки в код не писать.

Язык выбирается для перевода и входит в системный промпт перевода. Меню языка видно только при действии «Перевести». Список фиксированный, по порядку: английский, русский, немецкий, французский, испанский, итальянский, турецкий, китайский. По умолчанию выбран английский. У остальных действий языка нет: в запрос и в историю он не пишется.

Ввод не длиннее 4000 символов (`String.count`). Счётчик введённых символов виден. Запуск недоступен, если после обрезки пробелов и переводов строки текст пуст.

Результат появляется по мере генерации, не после полного ответа. Пока идёт стрим, на экране чистый текст результата, без подсветки. Пока ответ ещё не начался, видна загрузка.

После конца стрима, включая «Стоп» и ошибку, если текст результата уже есть, над результатом есть переключатель из двух режимов: «Результат» и «Изменения». Сразу после стрима выбран «Результат» — тот же чистый текст. «Изменения» — одна общая лента: удалённые слова красные зачёркнутые, добавленные зелёные, неизменённые обычным текстом. Цвета системные, отдельной палитры нет. Лента считается один раз методом `difference(from:)` стандартной библиотеки и в SwiftData не хранится. При просмотре правки она считается снова из сохранённых исходного текста и результата. Тот же переключатель есть на экране просмотра правки.

Слово — кусок между пробельными символами. Знаки препинания остаются при слове. Переводы строк — отдельные токены, чтобы абзацы сохранялись: в ленте такой токен остаётся переводом строки.

Для действия «Перевести» режима «Изменения» нет. Сравнивать по словам тексты на разных языках не нужно. Там «было — стало» — исходный текст и перевод двумя блоками, и на редакторе после стрима, и на экране просмотра.

Копирование всегда кладёт в буфер чистый текст результата, не подсветку и не ленту. Режим переключателя на это не влияет.

Во время генерации есть кнопка «Стоп». Нажатие отменяет задачу запроса и прекращает дописывание ответа.

При «Стоп» и при ошибке запроса уже пришедший текст результата сохраняется в истории вместе с исходным текстом, действием, языком перевода (если действие — перевод) и датой. Пустой результат в историю не пишется.

«Повторить» отправляет тот же запрос снова: тот же исходный текст, то же действие и тот же язык перевода. Вторую копию этого исходного текста не создаёт. Если запись этой попытки уже есть, повтор обновляет её результат, а не добавляет новую правку.

Ошибка «нет сети» и отдельная ошибка «кончился лимит API». У обеих есть кнопка «Повторить». Прочие сбои запроса показывают короткую ошибку и ту же кнопку «Повторить».

Пустой экран, когда смотреть нечего.

Интерфейс в духе iOS, светлая и тёмная тема через системное оформление. Все пользовательские строки и даты на русском. Лента результата и списки без `LazyVStack`.

Отдельного переключателя темы, вложений, расширения «Поделиться», Mac-таргета и выбора тона нет, пока их нет в подтверждённом плане.

История хранит только: исходный текст, результат, действие, язык, дату. Других полей не добавлять.

## Качество кода

- Экран рисует состояние и вызывает методы модели. Запрос к Groq, разбор SSE, сравнение слов и сохранение в SwiftData живут вне `View`.
- Модель экрана — `@Observable`. Модели хранения — типы SwiftData.
- Режим языка Swift 6. В рабочем пути нет принудительного разворачивания и `try!`. Ошибку показывает экран, а не пустой `catch`.
- «Стоп» отменяет задачу запроса, а не только прячет индикатор.
- Повтор не плодит вторую копию того же исходного текста.
- Цвета и шрифты системные, чтобы светлая и тёмная тема читались без отдельной палитры.
- `project.yml` не подключает пакеты. Таргет один: приложение `test`. Отдельного test target нет.
- Комментарий в коде — только там, где без него неясен контракт XOR.

## Критерии готовности

Шаг плана готов, когда схема `test` собирается под симулятор iPhone и изменения закоммичены.

Задание готово, когда одновременно верно следующее.

- Двойной клик по `Build.command` генерирует проект и собирает схему `test` под симулятор iPhone.
- В `project.yml`: Swift 6, iOS 18.0, только iPhone, bundle ID `com.yelzhanyelikbayev.aieditor`, отображаемое имя «AI-редактор», имя продукта, схема и таргет — `test`, пакетов нет.
- Имя модели записано одной константой `openai/gpt-oss-120b`.
- В `Secrets.swift` лежит непустой `obfuscatedKey`, соль `test.groq.v1`, открытого ключа в дереве файлов нет.
- Ручная проверка на симуляторе iOS 18 и на симуляторе последней iOS: результат приходит по частям; «Стоп» обрывает генерацию и сохраняет уже пришедший текст; после конца стрима для правки, кроме перевода, переключаются «Результат» и «Изменения»; у перевода видны два блока и нет режима «Изменения»; копируется чистый результат; меню языка есть только у «Перевести», по умолчанию английский; правка есть в истории после перезапуска и открывается из истории; пустой экран виден; ввод не длиннее 4000 символов и счётчик виден; без сети есть ошибка и рабочая «Повторить»; светлая и тёмная тема читаются.
- Ошибка лимита API показывается отдельно от «нет сети» и тоже даёт «Повторить». Если живой лимит при проверке не поймать, это прямо написано в README, а обработка 429 и квоты в коде есть.
- В репозитории лежат `docs/TASK.md`, `docs/PLAN.md`, этот `AGENTS.md` и корневой `README.md`.
- В репозитории есть папка `ai-logs/` с историей чатов, ключей в ней нет.
- README заполнен по шаблону из `docs/TASK.md`: инструменты, сервис и модель, что сделано, что не сделано и известные баги, как проверяли. Поле «Время» агент не оценивает — его ставит автор. После записанного автором финиша работу не продолжать.
- Коммиты идут по шагам плана, а не одним коммитом в конце.
- Расширение «Поделиться», Mac и выбор тона в приложении отсутствуют, пока отдельный подтверждённый шаг плана их не добавил.
