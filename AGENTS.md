# Правила работы над проектом

Это правила агента для тестового AI-чата. Источник задачи — `docs/TASK.md`. План шагов — `docs/PLAN.md` (составляется отдельно). Если требование здесь расходится с догадкой, выполняется этот файл.

Неясное спрашивать. Не додумывать экраны, тексты, API-поля и шаги, которых нет в задании, в этом файле или в плане.

## Зафиксированные решения

- Swift 6, SwiftUI, минимальная iOS 18.0. Приложение собирается и работает и на iOS 18, и на актуальной iOS. API новее iOS 18 не использовать.
- Только iPhone. Bundle ID `com.yelzhanyelikbayev.aichat`. Отображаемое имя — «AI-ассистент». Проект, схема и таргет — `test`.
- MVVM и `@Observable`. История чатов — SwiftData, переживает перезапуск.
- Зависимостей нет: ни CocoaPods, ни пакетов Swift Package Manager.
- Сеть только через `URLSession`. Ответ модели — поток SSE.
- AI: Groq, `POST https://api.groq.com/openai/v1/chat/completions`. Модель `openai/gpt-oss-120b`, в теле запроса `stream: true` и `reasoning_effort: "low"`. Ключ передаётся заголовком `Authorization: Bearer`.
- В пузырь и в историю пишется только текст ответа пользователю. Отдельные дельты рассуждений модели, если они приходят в SSE, на экран и в SwiftData не попадают.
- Проект описывает `project.yml` в корне. `xcodeproj` вручную не менять: его генерирует XcodeGen. Каталог `*.xcodeproj` остаётся в `.gitignore`.
- Корень репозитория — сама папка проекта. Исходники таргета лежат в `test/`. Существующий шаблон отсюда — стартовая точка. Перенос файлов только шагом плана.

## Секрет

Файл: `test/Services/Secrets.swift`.

Соль — строковая константа `test.groq.v1` (байты UTF-8) в этом же файле. Обфусцированный ключ — `static let obfuscatedKey: [UInt8]`. Байт `i` исходного ключа кодируется так:

`obfuscated[i] = keyUTF8[i] ^ saltUTF8[i % saltUTF8.count]`

Декодирование — тот же XOR. Пример для одного байта: символ `A` (`0x41`) и первый байт соли `t` (`0x74`) дают `0x35`.

Ключ не запрашивать и не искать. В репозиторий, логи, README и ответы не попадает открытый ключ. Массив байтов вставляет пользователь. Пустой массив или заглушка означают, что шаг с ключом не готов. Декодированная строка живёт только в памяти на время запроса: не писать её в логи, UserDefaults и SwiftData.

## Как работать

1. Следующий артефакт — `docs/PLAN.md`. Код приложения до отдельной просьбы выполнить шаг плана не писать.
2. Идти по шагам плана по порядку. Один шаг за раз. Шаг не расширять соседними задачами.
3. Конец шага: успешная сборка схемы `test` под симулятор iPhone и один git-коммит этого шага. Сломанную сборку не коммитить. Git config не менять, хуки не отключать, на remote не пушить без явной просьбы.
4. В корне лежит `Build.command`. Двойной клик в Finder запускает `xcodegen generate` и собирает схему `test` под симулятор iPhone, без команд в терминале. Когда файл уже есть, им и проверять шаг.
5. Фото во вложении, версия для Mac и офлайн Apple Foundation Models в объём не входят. Они появляются только отдельным пунктом `docs/PLAN.md`, который пользователь явно подтвердил.

## Функциональные требования

Приложение открывается сразу после сборки, без экрана настроек и ввода ключа.

- Чат с AI. Текст ответа появляется по мере генерации, не после полного ответа.
- Во время генерации есть кнопка «Стоп». Нажатие прекращает запрос и дописывание ответа.
- При «Стоп» и при ошибке запроса уже пришедший текст ответа сохраняется в истории.
- Несколько чатов. Можно создать чат и переключиться между ними. История на месте после перезапуска.
- Пустой экран, когда смотреть нечего.
- Загрузка, пока ответ ещё не начался.
- Ошибка «нет сети» и отдельная ошибка «кончился лимит API» (HTTP 429 и ответ Groq об исчерпании квоты или лимита). У обеих есть кнопка «Повторить»: тот же запрос уходит снова.
- Прочие сбои запроса показывают короткую ошибку и ту же кнопку «Повторить».
- Интерфейс в духе iOS, светлая и тёмная тема через системное оформление. Все пользовательские строки на русском.
- Отдельного переключателя темы, вложений, Mac-таргета и офлайн-модели нет, пока их нет в подтверждённом плане.

Состав экранов, пустые тексты сверх обязательных кнопок и схема SwiftData задаются в `docs/PLAN.md` и остаются внутри этих требований.

## Качество кода

- Экран рисует состояние и вызывает методы модели. Запрос к Groq, разбор SSE и сохранение в SwiftData живут вне `View`.
- Модель экрана — `@Observable`. Модели хранения — типы SwiftData.
- Режим языка Swift 6. В рабочем пути нет принудительного разворачивания и `try!`. Ошибку показывает экран, а не пустой `catch`.
- «Стоп» отменяет задачу запроса, а не только прячет индикатор.
- Повтор использует последнее пользовательское сообщение этого чата и не плодит вторую копию того же сообщения.
- Цвета и шрифты системные, чтобы светлая и тёмная тема читались без отдельной палитры.
- `project.yml` не подключает пакеты. Таргет один: приложение `test`. Отдельного test target нет.
- Комментарий в коде — только там, где без него неясен контракт XOR.

## Критерии готовности

Шаг плана готов, когда схема `test` собирается под симулятор iPhone и изменения закоммичены.

Задание готово, когда одновременно верно следующее.

- Двойной клик по `Build.command` генерирует проект и собирает схему `test` под симулятор iPhone.
- В `project.yml`: Swift 6, iOS 18.0, только iPhone, bundle ID `com.yelzhanyelikbayev.aichat`, отображаемое имя «AI-ассистент», имя продукта, схема и таргет — `test`, пакетов нет.
- В `Secrets.swift` лежит непустой `obfuscatedKey`, соль `test.groq.v1`, открытого ключа в дереве файлов нет.
- Ручная проверка на симуляторе iOS 18 и на симуляторе последней iOS: ответ приходит по частям; «Стоп» обрывает генерацию; два чата сохраняются после перезапуска; пустой экран виден; без сети есть ошибка и рабочая «Повторить»; светлая и тёмная тема читаются.
- Ошибка лимита API показывается отдельно от «нет сети» и тоже даёт «Повторить». Если живой лимит при проверке не поймать, это прямо написано в README, а обработка 429 и квоты в коде есть.
- В репозитории лежат `docs/TASK.md`, `docs/PLAN.md`, этот `AGENTS.md` и корневой `README.md`.
- В репозитории есть папка `ai-logs/` с историей чатов, ключей в ней нет.
- README заполнен по шаблону из `docs/TASK.md`: инструменты, сервис и модель, что сделано, что не сделано и известные баги, как проверяли. Поле «Время» агент не оценивает — его ставит автор.
- Коммиты идут по шагам плана, а не одним коммитом в конце.
- Фото, Mac и офлайн-режим в приложении отсутствуют, пока отдельный подтверждённый шаг плана их не добавил.
